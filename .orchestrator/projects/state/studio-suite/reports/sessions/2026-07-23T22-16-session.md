## Structure decisions

- **pnpm workspaces** via `pnpm-workspace.yaml` (authoritative). Dropped the npm-style
  `workspaces` field from root `package.json` — **pnpm 11 rejects it** and warns.
- **Web Vite skeleton isolated at `apps/web/app/`** (`index.html` + `main.tsx`), rooted
  there via `vite.config.ts` `root: "app"`. The Babel-standalone **prototype stays
  untouched at `apps/web/index.html`** and still opens/works (success criterion). Vite
  build output (`app/dist`) is gitignored. Feature migration is Session 02.
- **Web tsconfig scoped to `app/`** (was `src`, which holds the loose prototype `.jsx`

- **`packages/tokens`** got a `tsconfig.json` + `typecheck` script; consumed by both apps
  via `@illuminate/tokens` alias/symlink.
- **Mobile** `metro.config.js` for the monorepo (watchFolders = workspace root;
  nodeModulesPaths = app + root; `disableHierarchicalLookup`).

## Gotchas fixed (pnpm 11 + RN)

1. Apps declared `@illuminate/tokens: "*"` → pnpm 11 no longer implicitly links workspace
   packages, tried the npm registry (404). Fix: **`workspace:*`** protocol.
2. pnpm 11 blocks dependency build scripts → **esbuild** (Vite) postinstall ignored. Fix:
   `allowBuilds: { esbuild: true }` in `pnpm-workspace.yaml`.
3. **`.npmrc` `node-linker=hoisted` was silently ignored** — pnpm 11 reads these settings
   from `pnpm-workspace.yaml`, not `.npmrc`. The linker stayed `isolated`, so Metro could
   not resolve `@babel/runtime` helpers (expo export failed). Fix: moved `nodeLinker:
   hoisted` + `autoInstallPeers` into `pnpm-workspace.yaml`, removed `.npmrc`, clean
   reinstall. `@babel/runtime` then hoisted to root; export passes.
4. `pnpm exec` reconciliation tried to fetch rollup binaries for every platform
   (ppc64/s390x) over a flaky link. Fix: `supportedArchitectures: {os/cpu/libc: [current]}`
   (lockfile lists all; only current platform is installed). Also run app CLIs directly
   (`node_modules/.bin/expo`) to avoid the exec install-check.

## Pre-existing bug fixed

- `apps/mobile/src/theme/useTokens.ts` exposed `shadow(k: "sm"|"md"|"lg"|"gold")` but
  `shadowToRN` only supports `sm/md/lg` (no `"gold"` key in the RN `shadow` primitive —
  it's a web-only multi-layer box-shadow). Calling `shadow("gold")` would have crashed
  (`undefined.alpha`). Narrowed the type to match reality. No caller existed; behavior-
  preserving.
