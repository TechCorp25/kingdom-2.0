# Proposal — add common-ground rows to `gate-map.md`

**Target:** `automate-dev-suite/gates/gate-map.md` (complete replacement content below)
**Raised by:** common-ground integration session, 2026-07-25
**What changed:** two rows added at the end; **every existing row is unchanged,
verbatim, in its original order.** Nothing is removed, reworded, or reclassified.

**Why:** the common-ground skill writes assumption state under
`.orchestrator/projects/state/{p}/patterns/common-ground/`. Without a row, the
action is unlisted, and the `gate-check` skill resolves an unlisted action to
"the nearest listed analogue, or HARD if genuinely novel" — which in practice
puts an owner stop in front of every routine assumption record. The
proposed class matches the existing precedent for state-file writes — "Memory
promotion, reports, session-goals files | go" — because it is the same kind of
action: local, reversible, file-I/O-only, no model calls, no network.

The second row is defensive rather than permissive: it states explicitly that
changing the skill or script itself is self-check (PR readiness), matching
`risk-envelope.md` ("Inside the envelope", first bullet), which already places
kingdom-repo skills and workflows inside the Fable envelope. Weakening a guard
remains HARD via the existing row — this proposal does not touch that.

**Promote with:**

```bash
git mv automate-dev-suite/gates/_proposals/2026-07-25T08-46-44-gate-map.md \
       automate-dev-suite/gates/gate-map.md
```

Reject by deleting this file — the skill then operates under the HARD default,
which is safe but will prompt on every assumption write.

# Gate map — which class governs which action

Hard rules in `gates.md` §1 always apply on top of this map.

| Workflow / action | Gate class |
|---|---|
| **Kingdom bootstrap** — pull ff-only when behind | go |
| Kingdom `main` diverged | **HARD** |
| **Project bootstrap** — ff-pull / push / stash-and-branch | go |
| Project history diverged | **HARD** |
| Session remediation (promote crashed session) | go |
| **PR readiness** — session work complete, checks green, PR opened/refreshed for the owner (kingdom or project) | self-check |
| **Any merge to `main`** (kingdom or project repo) | **HARD** (owner-only, performed by the owner; owner's report-back triggers session close) |
| Suite hook/permission changes (`.claude/settings.json`, guards) | self-check |
| Weakening or removing a guard/gate/boundary rule | **HARD** |
| Project PR touching auth, payments, data deletion, or migrations | **HARD** (flag in the PR body for the owner's merge review) |
| Dependency updates — patch/minor, lockfile clean | self-check |
| Dependency updates — major version | **HARD** |
| **New project creation** (repo on owner's GitHub, private) | self-check |
| Making any repo public, deleting a repo/branch with unmerged work | **HARD** |
| Deployment to a hosted service (EAS, Railway, …) | **HARD** (keys + go/no-go are the owner's) |
| Security finding high/critical — merge despite it | **HARD** |
| Security finding medium/low — fix lands in normal PR | self-check |
| Memory promotion, reports, session-goals files | go |
| Modifying `gates/`, `gate-map.md`, `risk-envelope.md` | **HARD** |
| **Common ground** — recording/adjusting assumptions (`common-ground.sh add`/`tier`/`validate`/`graph`) | go |
| Changes to the common-ground skill or script itself | self-check |
