# Policy — Python / FastAPI gotchas (hard-won in v1)

Applies whenever a project in this kingdom uses Python/FastAPI. Each entry
cost real debugging time; check them before "obvious" fixes.

## `from __future__ import annotations` + FastAPI = HTTP 422

Do **NOT** add `from __future__ import annotations` to any module used as a
FastAPI class-instance `Depends()`, or to route files. It turns annotations
into strings, so FastAPI mis-reads a request/dependency param as a query field
and the endpoint returns HTTP 422 on every call.

- Concretely bit `backend/security/rate_limit.py` in v1 (all rate-limited
  routes 422'd) and recurs in route files. When in doubt, leave it out of
  route/Depends modules.
- It is fine (and useful) in plain library/service/script modules.

## Test-harness patterns that worked (IlluminateMyGallery backend, v1)

- `mongomock_motor` backing a lazy `db._db`; `litellm` stubbed via
  `sys.modules`.
- Reset rate limiters between tests (`get_limiter().reset()` in an autouse
  fixture) — leaked limiter state produces order-dependent test failures.
- Mock cloud SDKs at the adapter boundary (`unittest.mock.patch` on boto3) —
  never hit real object storage from tests.

## General

- Async DB access only, through a single `session_scope()`-style helper that
  owns commit/rollback/close — never ad-hoc session handling per call site.
- Keep business logic in one service layer shared by every surface (API, CLI,
  MCP) so surfaces cannot diverge.
- Strict mypy from day one is cheaper than retrofitting it.
- Review autogenerated migrations before applying; deterministic constraint
  naming keeps autogenerate diffs reviewable.

## v2 suite-specific

- JSON-reading **hooks** must NOT use `python3 - <<heredoc` — the heredoc
  consumes the hook's stdin, silently disabling the hook's input parsing
  (caught in v2 guard testing: it disabled all denies). Use
  `python3 -c "...sys.stdin..."` in hooks; heredocs are fine in ordinary
  scripts.
